# OpenAI SDR Rapid-Fire Mock And Delivery Drill

Navigation: [[OpenAI-SDR-master-interview-prep-checklist]] | [[OpenAI-SDR-live-mock-interviewer-script]] | [[OpenAI-SDR-P0-rehearsal-execution-log]] | [[OpenAI-SDR-comprehensive-answer-expansion-bank]]

Internal rehearsal sheet for Seth's OpenAI Strategic BDR APAC interview loop. Use this to convert drafted answers into speakable answers under time pressure.

## Read This First

- Status: `Drafted`, not `Rehearsed` or `Ready`.
- This is an internal drill sheet. Use [[OpenAI-SDR-comprehensive-answer-expansion-bank]] for anything visible.
- Use [[OpenAI-SDR-live-mock-interviewer-script]] when the mock needs to be run by a person, Codex, or a self-timer with score capture.
- The goal is not to memorize every sentence. The goal is to make the answer spine automatic.
- Later rounds may repeat the same question. Answer consistently, shorter each time, without looking annoyed.
- Default tone: serious, direct, warm enough, no joke-forward energy, no robotic recital.

## Delivery Rules

| Rule | Why it matters | Live habit |
|---|---|---|
| Lead with the answer | Time-pressured interviewers need signal fast. | First sentence should answer the question directly. |
| Proof before philosophy | Avoid sounding abstract or over-coached. | Name one Seth proof point quickly. |
| Customer before product | Commercial rounds test value-based selling. | Start with buyer priority, workflow, stakeholder, or risk. |
| No fake certainty | Product/security facts can change. | "I would verify the exact detail, but my working understanding is..." |
| Shorter on repeat | VP rounds may re-ask RAG/hallucination/deal questions. | "Same answer in shorter form..." |
| Bridge to OpenAI | Every story should explain why it matters here. | "The OpenAI parallel is..." |
| Stop cleanly | Rambling weakens good answers. | End with a crisp lesson or next step. |

## Answer Timeboxes

| Timebox | Shape |
|---:|---|
| 15 seconds | Direct answer only. One sentence plus proof phrase. |
| 30 seconds | Answer, one proof point, OpenAI relevance. |
| 60 seconds | Answer, proof, business logic, lesson. |
| 90 seconds | Use when asked for a story but not "walk me through." |
| 2-3 minutes | Deal walkthrough, career walkthrough, or case defense only. |

## Recovery Lines

| Situation | Line |
|---|---|
| You do not know a product/security detail | "I would not want to improvise that. I would verify the current OpenAI source and bring in the right technical or security resource." |
| Metric uncertainty | "I want to be precise rather than inflate it. The exact number I would confirm, but the verified directional proof is..." |
| Asked the same question again | "Same answer, shorter: the key point is..." |
| Started too technical | "Let me bring that back to the buyer problem." |
| Started too broad | "The practical version is..." |
| Need a pause | "Let me think for one second because I want to give you the clean version." |
| Challenge on SDR step-back | "That is a fair question. I see it as optimizing for learning slope and account complexity, not title." |
| Competitor challenge | "I would not frame this as rip-and-replace. I would first understand what is already working and where the gap remains." |

## Universal Pass Criteria

An answer passes if it is:

- under the target time;
- customer-value led;
- Seth-specific;
- honest about uncertainty;
- free of unsupported OpenAI claims;
- connected to the role;
- delivered without reading.

## Delivery And Logistics Checklist

### Day Before

- [ ] Confirm calendar, time zone, Zoom link, interviewer name/title, and stage.
- [ ] Confirm actual case prompt/deadline if relevant.
- [ ] Re-read only the screen-share-safe prep doc and the one stage-specific artifact.
- [ ] Check top 10 rapid-fire questions for the next round.
- [ ] Prepare one stage-specific question to ask.
- [ ] Verify any current product/account facts that may be mentioned.
- [ ] Close private notes, raw source folders, compensation/process notes, and unrelated apps.

### 60 Minutes Before

- [ ] Camera, mic, lighting, background, charging, internet.
- [ ] Office shirt; no suit unless Seth prefers.
- [ ] Water nearby.
- [ ] Only safe tabs open: calendar, Zoom, screen-share-safe prep doc, optional resume.
- [ ] Notifications off.
- [ ] Desktop cleaned.

### 15 Minutes Before

- [ ] One 30-second intro aloud.
- [ ] One why OpenAI aloud.
- [ ] One RAG aloud.
- [ ] One hallucination aloud.
- [ ] One deal-card headline aloud.
- [ ] One "why SDR" aloud.
- [ ] Breathe, slow down, answer the question asked.

### During The Call

- [ ] Smile at start, then settle into serious/warm.
- [ ] Use first names naturally.
- [ ] Listen fully before answering.
- [ ] Ask a clarifying question only when it changes the answer.
- [ ] Keep hands off keyboard unless taking light notes.
- [ ] Do not visibly search raw notes.
- [ ] If screen sharing, share the doc window only, not entire desktop.
- [ ] Stop when the answer is complete.

### After The Call

- [ ] Write down questions asked.
- [ ] Mark weak answers.
- [ ] Capture any new process or evaluation signal privately.
- [ ] Update master checklist if a new question appears.
- [ ] Send follow-up only if requested or strategically appropriate.

## Red Flags To Avoid

- Sounding like OpenAI is only brand prestige.
- Sounding entitled to a fast promotion.
- Treating SDR as beneath Seth.
- Saying "100% no hallucination."
- Making unsupported security, privacy, compliance, or model claims.
- Leading with "OpenAI is better/cheaper."
- Attacking competitors.
- Using Stanley's facts as Seth's facts.
- Turning every answer into a builder monologue.
- Trying to be too clever or outside the mold.
- Showing private notes or raw AI outputs on screen.
