Internal control page for finishing the Loom case once Seth has the actual prompt.

## Read This First

- This page is not a case answer. It is the operating checklist for the final case workflow.
- Do not record from stale facts. Recheck the assigned account and exact OpenAI product claims on the day of recording.
- Use [[OpenAI-SDR-DoorDash-Loom-final-canonical-document]] if the prompt names DoorDash and Seth is including the live Dasher reactivation voice demo.
- Treat [[OpenAI-SDR-DoorDash-Loom-current-strategy-script]] as source/reference only.
- Use [[OpenAI-SDR-DoorDash-Loom-case-fallback]] only if the DoorDash answer should focus on consumer commerce / intent-to-cart instead of the live demo.
- Use [[OpenAI-SDR-Loom-case-package]] / IHH only if the prompt allows an open-choice APAC account.
- Keep raw process intelligence, compensation, hiring-count, reference-signal, and warm-path details out of any deck, Loom, or screen-share surface.

|---|---|---|

Decision line to write before building:

> I am choosing `<account>` because `<prompt requirement>` and `<business value wedge>`. I will not reuse any facts from a different account.

## Final Verification Checklist

### Target Account

Verify from primary/current sources:

- [ ] Company description and scale.
- [ ] Current revenue/order/customer/market figures if used.
- [ ] Strategic priorities or recent public initiatives.
- [ ] Existing AI announcements or partnerships.
- [ ] Account-specific risk constraints.
- [ ] Names/titles of any executives only if needed and current.

Do not use:

- stale specimen figures;
- third-party blog summaries when primary sources exist;
- guessed org charts;
- claims that the customer is not already using AI unless public evidence supports it.

### OpenAI Claims

Check [[OpenAI-SDR-comprehensive-answer-expansion-bank]] and official OpenAI sources before saying exact claims about:

- product names and packaging;
- model names or capabilities;
- API data controls;
- enterprise security/privacy/admin controls;
- pricing, rate limits, quotas, or latency;
- region, inference location, storage, or residency;
- healthcare, regulated-industry, HIPAA/BAA, or compliance details.

Safe default:

> I would validate exact product, security, and deployment details with current OpenAI documentation and the right technical resource before making a customer commitment.

### Forbidden Or High-Risk Claims Scan

Search the deck/script before recording for:

| Term or claim type | Action |
|---|---|
| `gpt-5.2` or specimen-only model IDs | Remove unless current official docs and account use case justify it. |
| `OpenAI Frontier` as a product/SKU | Remove unless official prompt confirms it as a product name. |
| HIPAA, BAA, residency, hosting, inference region | Remove unless officially verified and appropriate. |
| Exact price, rate limit, quota, latency | Remove unless officially verified. |
| "100% avoids hallucination" | Replace with mitigation framing. |
| "rip and replace" competitor wording | Replace with land-and-expand. |
| Friend/process details | Remove from all visible materials. |

## Deck And Script Workflow

Use the smallest artifact that can carry the case cleanly.

| Time available | Workflow |
|---|---|
| Full day | Finalize account choice, recheck facts, adapt 6-slide deck, write timing script, record two practice takes, send reviewer packet, record final take. |
| 3 hours | Use existing 6-slide structure, verify only claims used aloud, record one rough timing pass, fix top two issues, record final take. |
| 90 minutes | No fancy redesign. Use a simple deck or talking outline, verify only critical facts, record one clean take, submit. |

Recommended 6-slide structure:

1. Why Seth / why OpenAI.
2. Account point of view.
3. One high-impact use case.
4. How it works technically.
5. 30-day executive engagement plan.
6. Outbound message and standout approach.

Timing target:

| Segment | Time |
|---|---:|
| Why Seth / why OpenAI | 60-90s |
| Account POV | 60s |
| Use case | 90s |
| Technical workflow | 75s |
| 30-day plan | 75s |
| Outbound / standout close | 45-60s |

Hard stop: keep final recording under the stated limit.

## Recording Runbook

Before recording:

- [ ] Close private notes, raw transcripts, email, compensation/process notes, and unrelated apps.
- [ ] Open only final deck/script and safe prep material.
- [ ] Confirm microphone, camera, lighting, browser tab, and notifications.
- [ ] Record one timing rehearsal.
- [ ] Cut or simplify any section that causes time overrun.
- [ ] Check that the opening sounds like Seth, not a generic AI pitch.

During recording:

- [ ] Lead with the answer.
- [ ] Speak at normal speed.
- [ ] Do not over-explain technical architecture.
- [ ] Make the case about business priority, workflow, stakeholders, and measurable outcome.
- [ ] End with one crisp standout line.

After recording:

- [ ] Watch the first 30 seconds.
- [ ] Watch the transition into the use case.
- [ ] Watch the final 45 seconds.
- [ ] Confirm audio is clear.
- [ ] Confirm no private tabs or filenames are visible.
- [ ] Confirm the Loom sharing setting works in an incognito/private window.

## Reviewer Packet

Send the reviewer only the final share-safe materials:

- Loom link.
- Deck PDF if using slides.
- One-line prompt summary.
- Specific feedback request.

Reviewer message:

```text
Hey, could you pressure-test this OpenAI Loom before I submit?

What I need most:
1. Does the account thesis sound specific and commercial?
2. Is the use case clear in one sentence?
3. Does the 30-day engagement plan sound like a seller could actually run it?
4. Any obvious overclaim or confusing technical point?
5. Does it feel concise enough for the time limit?

No need to rewrite it unless something is clearly broken.
```

## Submission Packet

Before submission:

- [ ] Final Loom link works for someone outside Seth's account.
- [ ] Deck PDF exported if useful.
- [ ] File name is clean and professional.
- [ ] Submission form is complete.
- [ ] Backup email is prepared if appropriate.
- [ ] Calendar reminder exists for follow-up.

Backup recruiter email:

```text
Hi <Name>,

I have submitted the Loom through the assignment link as requested. Sharing the Loom link here as a backup as well: <link>

I have also attached the deck PDF for reference.

Best,
Seth
```

Only send a backup email if it fits the recruiter instructions.
