## Product And Technical Fluency

### Enterprise Adoption Ladder

- One-line:
  - Sell OpenAI as an adoption ladder where work compounds: Codex -> Workspace Agents -> Frontier/deployment.
- Stage 1: Codex / work-surface adoption.
  - Engineering: understand codebase, make changes, run checks, review PRs, debug, maintain.
  - Knowledge work: research, synthesize docs, analyze spreadsheets, draft reports, prep meetings, generate internal tools.
  - Value = individual/team leverage.
- Stage 2: Workspace Agents / shared workflow adoption.
  - Built once, reused by team.
  - Lives in ChatGPT/Slack.
  - Cloud-running.
  - Tool-connected.
  - Triggerable from ChatGPT, Slack, schedule, API.
  - Governed by admins, approvals, sharing controls.
  - Best for bounded workflows with SOP, source systems, approval path, output.
  - Pilot traits: high volume, repetitive judgment, clear sources, canonical SOP, eval set, reviewer.
- Stage 3: Frontier / FDE-style deployment.
  - Strategic operating-model redesign.
  - Many agents and teams need shared business objects, integrations, evals, governance, permissions, change management.
  - Example context graph:
    - Account, Contact, Opportunity, Renewal, Incident, Policy, Approval, Discount Exception, Risk, Next Step, CRM Writeback.
    - Not just final CRM state, but decision trace.
- BDR job:
  - Qualify highest credible next stage.
  - Do not oversell transformation too early.
  - Find workflow, owner, proof, buying committee.

### Codex / Cursor / Claude Code / OpenCode Objection

- One-line:
  - Do not say competitors are weak; argue model-plus-harness, multimodal/work-surface breadth, and enterprise standardization.
- Say:
  - "ChatGPT is becoming the horizontal super app for work; Codex is its engineering workbench and part of the execution layer underneath it."
- Arguments:
  - First-party model plus harness fit.
  - Repo context, tools, terminal execution, tests, browser validation, diffs, approvals, worktrees, review paths.
  - Model and harness co-evolve.
  - Same model can perform differently in different harnesses.
  - OpenAI has broader first-party multimodal estate: text, reasoning, coding, vision, images, realtime voice, speech/transcription/translation, video, embeddings/retrieval, tools, computer use.
  - Enterprise standardization: one control plane, admin/governance, less shadow AI, reusable process across teams.
- Do not say:
  - Claude/Cursor are bad.
  - Claude is not multimodal.
  - Every engineer must prefer Codex.
- Discovery:
  - What do engineers use today?
  - Is the problem individual speed or org-wide SDLC standardization?
  - What governance, data, repo, approval, and audit controls matter?
  - What would make a team rollout safe?

### Workspace Agents Versus n8n / Workflow Automation

- One-line:
  - Judgment belongs in agents/skills; deterministic orchestration belongs in workflow runtimes; mature pattern is often hybrid.
- Use Workspace Agent when:
  - Repeatable but judgment-heavy.
  - Reads messy context.
  - Applies rubric.
  - Uses examples.
  - Drafts recommendation.
  - Needs human approval.
  - SOP improves over time.
- Use n8n/Workato/Make/Zapier/Salesforce Flow when:
  - Trigger, branch, API call, transform, update, retry, log.
  - Stable rules.
  - High volume.
  - Low judgment.
  - Need node-level execution observability.
- Hybrid:
  - Workflow runtime handles trigger, validation, enrichment, logging, final writes.
  - Workspace Agent applies skill, drafts brief, recommends action, asks approval.
- Good sound bite:
  - "Rent the frontier when speed, model fit, governance, and adoption matter. Own the harness when portability and custom control matter. Either way, the customer should own the judgment."
- Examples:
  - Lead routing:
    - Workflow tool = territory/threshold assignment.
    - Agent = is account strategically worth pursuing now?
  - Support:
    - Workflow tool = ticket routing/escalation.
    - Agent = policy/context review and draft response for approval.
  - Weekly reporting:
    - Workflow = distribute numbers.
    - Agent = interpret pipeline risk and actions.
  - Finance/compliance:
    - Workflow = sync approved invoice.
    - Agent = pre-approval review and exception packet.

### Model-Router / Best Model This Week Objection

- One-line:
  - Model routing is valid, but production AI quality is workflow-specific, eval-led, and operationally expensive.
- Acknowledge:
  - Different models can win different jobs.
  - Price-performance changes quickly.
- Pushback:
  - "Best" depends on prompt, provider, tools, latency, cost, safety, UX, output format.
  - Model is one piece of system.
- Lindy migration lesson:
  - Cost savings required offline evals, candidate testing, provider testing, prompt optimization, internal rollout, online evals, retention checks, gradual ramp.
  - "Changing model name was easy; proving trust was hard."
- OpenAI argument:
  - Fewer moving parts for important workflows.
  - Model, harness, work surfaces, SDKs, traces, eval guidance, governance, migration patterns together.
  - Codex/Workspace Agents come batteries included.
- Discovery:
  - What tasks are routed?
  - What does good mean?
  - Offline evals?
  - Online evals/traces?
  - Who owns routing policy?
  - What data goes to which providers?
  - What actions require approval?
- Do not say:
  - Never use other models.
  - Cheaper model is always worse.
  - Routing is simple.

### Explain An LLM Simply

- One-line:
  - An LLM is a prediction system trained to generate the next token, but enterprise value comes from the harness around it.
- Core:
  - Tokens = small units of text/data.
  - Pretraining = broad base capability from predicting next token at scale.
  - Post-training = turn predictor into assistant with examples/preferences.
- Product point:
  - It can summarize/classify/extract/reason/draft because it learned patterns.
  - But reliability depends on context, tools, output format, permissions, evals, latency/cost, human review.
- Sound bite:
  - Model = intelligence layer.
  - Harness = product system.

### Reasoning Models

- One-line:
  - Reasoning models spend more internal compute on harder multi-step tasks; tradeoff is latency/cost.
- Use when:
  - Complex account analysis.
  - Security review.
  - Regulated workflows.
  - Agentic coding.
  - Support escalation.
  - Multi-step operational work.
- Do not use everywhere:
  - Simple classification, formatting, lookup may need faster/cheaper model.
- Buyer question:
  - What is cost of wrong answer?
  - What latency is acceptable?
  - What do evals show?

### Explain An Agent Simply

- One-line:
  - Instructions, model, and tools running in a loop.
- Agent loop:
  - Read state.
  - Decide next step.
  - Use tool or produce output.
  - Observe result.
  - Continue until done or human needed.
- Tools:
  - Read: files, glob, grep/search.
  - Edit: write/edit.
  - Execute: shell/API.
  - Delegate: helper agent.
- Planning:
  - To-do list before acting.
  - Harness re-injects plan so model does not drift.
- Browser vs computer use:
  - Browser = webpage structure/DOM/accessibility tree.
  - Computer = screenshots + mouse/keyboard; more general, more brittle.
- Enterprise agent output:
  - Work packet, not just text.
  - Summary, sources, tool calls, recommended action, confidence, risk label, approval status.
- Harness pieces:
  - Context.
  - Retrieval/source truth.
  - Tools.
  - Skills.
  - Sandbox.
  - Structured outputs.
  - State/memory.
  - Permissions/scope.
  - Evals.
  - Tracing/logs.
  - Latency/cost controls.
  - Human review/escalation.
  - Feedback loop.

### RAG

- One-line:
  - RAG makes AI answer from approved current company knowledge, not generic memory.
- Core:
  - Search approved knowledge first.
  - Pass relevant context to model.
  - Model answers using evidence.
- Not just embeddings:
  - Keyword/BM25 for exact anchors.
  - Embeddings for semantic match.
  - Metadata for scope/permissions/freshness.
  - Reranking for better evidence.
  - Citations for inspection.
- Why it matters:
  - Current policies, account notes, product docs, legal/healthcare/bank knowledge.
- Long context caveat:
  - Helps but does not replace retrieval.
  - Company corpus too large/noisy/permissioned.
- Failure modes:
  - Wrong source.
  - Stale source.
  - Bad chunking.
  - Missing metadata.
  - Permission leak.
  - Model overstates evidence.
- Good buyer line:
  - "Better version is not 'we embedded docs.' It is governed retrieval that finds the right source, checks allowed/current, shows evidence, then reasons over it."

### Fine-Tuning

- One-line:
  - Fine-tuning changes behavior; it is not the default way to upload current company knowledge.
- Use RAG/File Search for:
  - Current policies.
  - Pricing.
  - Account notes.
  - Product docs.
  - Permissioned/current knowledge.
- Fine-tuning can help:
  - Style.
  - Terminology.
  - Output structure.
  - Decision patterns.
  - Domain habits.
  - Repeated failure pattern with enough clean examples/evals.
- Healthcare example:
  - RAG supplies patient/policy context.
  - Fine-tuning helps model follow report-review pattern or domain terminology.
- Bad fine-tuning risks:
  - Stale facts.
  - Overfitting.
  - Behavior drift.
  - Harder audit.
- Sequence:
  - Model choice -> prompting/examples -> retrieval -> tools -> structured outputs -> evals -> fine-tune only if repeated measurable failure persists.

### Hallucination

- One-line:
  - Hallucination is often a context-engineering failure, not just "model dumb."
- Causes:
  - Wrong file.
  - Stale data.
  - Missing info.
  - No source-of-truth tool.
  - Model eager to complete task.
- Enterprise answer:
  - Right context.
  - Right tools.
  - Constrained output.
  - Human review for high stakes.
  - Representative evals.
- Regulated buyer line:
  - "I would not sell certainty. I would sell a controlled workflow: right context, right tools, measurable behavior, visible failures, and review paths."

### Evals

- One-line:
  - Evals turn AI quality from vibes into an operating loop.
- Components:
  - Dataset.
  - Run/trace.
  - Graders.
  - Human SME review where needed.
- Measure:
  - Correctness.
  - Source grounding.
  - Tone.
  - Judgment.
  - Tool use.
  - Escalation behavior.
  - Cost/latency.
  - Failure handling.
- Dataset sizing:
  - 5-10 cases for first obvious failures.
  - 20-50 high-signal cases for regression baseline.
  - Tens/low hundreds for production, edge cases, high-risk workflows.
- Support-ticket example:
  - Duplicate charge.
  - Agent checks Salesforce, Stripe, Notion refund SOP.
  - Drafts empathetic response.
  - Recommends refund.
  - Requests billing approval before money movement.
- Improvement levers:
  - Prompt/instructions.
  - Retrieval/source quality.
  - Mandatory tool flow.
  - Approval gate.
  - Structured output/schema.
  - Permissions/metadata/freshness.
  - Model choice/examples/fine-tune.
  - Regression evals.

### CLI Versus MCP

- One-line:
  - CLI can be faster for local one-off agent work; MCP is stronger for shared enterprise governance.
- CLI advantages:
  - Agent composes commands.
  - Filters output with tools like `jq`.
  - Faster debugging.
  - Compact evidence packets.
  - Good for local engineering / one-off analysis.
- CLI caveat:
  - Still needs auth/permissions.
- MCP advantages:
  - OAuth.
  - Approved tool boundaries.
  - Auditability.
  - Shared enterprise access.
  - Safer workspace integration.
- Commercial answer:
  - Agent ergonomics matter.
  - Model plus harness: context, tools, permissions, evals, traces, review, compact outputs.

### Deal Quality And Judgment

#### Early-Stage Opportunity Realness

- One-line:
  - Look for buyer behavior, not rep optimism.
- Real signals:
  - Urgency: why now, what breaks, business priority.
  - Buyer co-authorship: corrects POV, defines proof, shares internal context, shapes business case.
  - Champion quality: knows who must believe and helps reach them.
  - Concrete validation path: named use case, missing proof, technical/security/procurement owners, near-term next step.
- OpenAI version:
  - Usage/AI curiosity is signal.
  - Real pipeline needs named workflow, business owner, proof plan, AD path.
- Red flag:
  - "Send deck/case study" without internal ownership.

#### Real Champion

- One-line:
  - A real champion can move the deal when I am not in the room.
- Three traits:
  - Pain: business consequence of doing nothing.
  - Power path: knows economic buyer, finance, security, legal, procurement, users, blockers.
  - Internal courage: spends credibility, corrects us, intros when reason exists, prepares for CFO/security pushback.
- Test:
  - Can they explain why now, why this workflow, why OpenAI, risk, proof still needed?
- Not champion:
  - Likes product, responds quickly, says "send me more."

#### Disqualify Or Slow Down

- Slow down when:
  - Enthusiasm but no buying process.
  - No business pressure.
  - No named workflow.
  - No owner.
  - No reason now.
  - Friendly user but no path to power.
  - Missing proof criteria.
  - High-risk use case but no governance/security/review/implementation capacity.
- Action:
  - Re-qualify around urgency, stakeholders, proof, implementation.
  - Move to nurture if trigger absent.
  - Protect AD from happy-ear pipeline.

#### Champion Enablement

- Champion often stalls because not safe to advocate.
- Enable with:
  - Internal memo.
  - Business case.
  - Implementation path.
  - Security answers.
  - Risk framing.
  - Proof points.
  - Stakeholder-specific talk tracks.
- Goal:
  - Help champion convince organization, not just like us.

#### Buyer Co-Authorship

- Better than polished vendor pitch.
- Ask:
  - What proof matters?
  - Who will object?
  - What internal story makes decision safe?
  - What would buyer add/change?

#### Stalled Deal

- Diagnose before follow-up:
  - Missing pain?
  - Missing stakeholder?
  - Missing proof?
  - Weak champion?
  - Procurement/security risk?
  - Bad timing?
  - No urgency?
- Generic "checking in" rarely fixes real issue.

#### Discount-Led Selling

- Do not lead with price before value/urgency/fit.
- Discounts solve procurement friction, not problem belief or solution belief.

  - "For people who have grown successfully from this role, what did they demonstrate in the first 6 to 12 months?"
  - "What separates high activity from someone trusted with larger account responsibility?"

### Delivery Tone

- Serious, crisp, normal, slightly warm.
- First sentence answers directly.
- Add one proof point.
- If challenged, tighten instead of defending.
- Seller depth for product unless asked deeper.
- Bring specialist resources for security/legal/pricing/deployment details.
- Screen share only sanitized surface.
- After each round:
  - Thank-you.
  - Log weak answers.
  - Repair before next interview.
