# Design System Kickoff

Before designing or building a new UI, look for an existing design system or AI-readable style reference to anchor the project.

## Required Sources

Always check both:

- `https://github.com/alexpate/awesome-design-systems` — broad catalog of public design systems, including tags for components, voice and tone, designer kits, and source code.
- `https://styles.refero.design/` — searchable DESIGN.md examples with colors, typography, spacing, components, and product-style references for AI agents.

## Workflow

1. Infer the project type, domain, audience, and product feel from the user request.
2. Browse the required sources for 2-4 plausible reference systems or styles.
3. Pick one primary reference and, if useful, one secondary contrast reference. Prefer systems with public docs, components, source code, or clear DESIGN.md details.
4. Extract only the useful starting constraints: color direction, type scale, spacing rhythm, component density, navigation patterns, tone, and accessibility posture.
5. State the chosen references and why they fit before building. Adapt the references to the product; do not copy a brand identity unless the user explicitly asks and has rights to it.
6. Use the selected references to seed tokens, component choices, layout density, and visual QA for the project.

If neither source yields a good match, say so and define a small provisional design system from first principles.
